# תוכנית: התחברות אמיתית + הגנה על הטלפון

נכתב 2026-10-26. מטרה: שמספר הטלפון והשם המלא יהיו באמת מוגנים, ושאי אפשר יהיה להתחזות או לשנות נתונים של אחרים.

## למה צריך
- היום אפשר להוריד את כל המשתמשים כולל טלפון ושם מלא עם המפתח הציבורי, בלי התחברות (אומת 26.10).
- ה"התחברות" היא רק רשומה בדפדפן; הקוד במייל נבדק בדפדפן. Firestore לא יודע מי שואל → אי אפשר לכתוב חוקים שמגנים.
- Google כבר עובר דרך Firebase Auth — צריך להעביר גם את המייל.

## מה ישתנה למשתמשים
- **מייל:** במקום קוד בן 6 ספרות — **קישור התחברות במייל** (לוחצים ונכנסים). Google — כמו היום.
- **משתמשים קיימים:** פעם אחת יתבקשו להתחבר מחדש (Google או קישור במייל). הפרופיל, התמונות, הלייקים והצ'אטים נשארים.
- **טלפון:** עובר למקום נפרד שרק הבעלים ומי שיש איתו קונקשן יכולים לקרוא.

## שלבים (כל שלב → בדיקה → אישור לפני הבא)

| שלב | מה | מי |
|-----|-----|-----|
| **0** | בקונסול Firebase: Authentication → Sign-in method → להפעיל **Email link (passwordless)** (תחת Email/Password). Google כבר פעיל. | את/ה (2 דק׳) |
| **1** | התחברות: `register.html` — שליחת קישור במייל (`sendSignInLinkToEmail`) וקליטתו; Google נשאר. `auth.js` — הסשן נשען על `firebase.auth()`; כל דף טוען את Firebase Auth. EmailJS-OTP יוצא. | אני |
| **2** | משתמשים קיימים: מי שיש לו סשן ישן בלי התחברות אמיתית → מסך קצר "התחבר/י שוב" (פעם אחת). | אני |
| **3** | הטלפון במקום נפרד: `users_private/{id}` = `{ phone }`. כתיבה בהרשמה ובעריכה; קריאה רק כשיש קונקשן (וואטסאפ/צ'אט). הסרת `phone` ממסמך `users`. | אני |
| **4** | העברת מספרים קיימים: כפתור חד-פעמי באדמין שמעתיק טלפונים ל-`users_private` ומוחק מ-`users`. | אני + את/ה (לחיצה) |
| **5** | חוקים מהודקים ב-`firestore.rules`: כל אחד עורך רק את הפרופיל שלו; לייק/בקשה רק בשם עצמך; צ'אט רק לשני המשתתפים; פעילות — יוצר/ת עורך/ת, אחרים רק מצטרפים/עוזבים; `users_private` רק לבעלים ולקונקשנים. | אני כותב, את/ה מפרסם/ת |
| **6** | ניקוי: הסרת השם המלא מהדפים הציבוריים (רק שם פרטי + אות), עדכון CLAUDE.md, טסטים, מטמון. | אני |

## סיכונים ואיך נמנעים
- **נעילה בטעות:** חוקים מהודקים מפורסמים **רק אחרי** שהקוד החדש באוויר ונבדק. לפני פרסום — בדיקה ב-Rules Playground בקונסול.
- **משתמשים שלא יתחברו מחדש:** הפרופיל שלהם נשאר גלוי ופעיל; הם רק לא יוכלו לערוך עד שיתחברו.
- **קישור במייל נפתח בדפדפן אחר** (למשל מאפליקציית המייל): Firebase מבקש להקליד שוב את המייל — זה טופל במסך הקליטה.
- **אפשר לחזור אחורה** בכל שלב דרך Vercel (Promote לגרסה קודמת), ובחוקים — הדבקת הגרסה הקודמת מ-git.

## מחוץ לתוכנית (אחר כך)
- הגבלת כמות בקשות הודעה ביום, חסימה/דיווח מתוך בקשה.
- הצפנה/הסתרה של המייל עצמו (היום מזהה המסמך = המייל).
